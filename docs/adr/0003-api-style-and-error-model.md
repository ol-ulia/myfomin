## ADR 0003: Стиль API та Модель Помилок

- **Назва:** Впровадження Стилю RESTful API та Єдиного Формату Помилок  
- **Статус:** Прийнято  
- **Дата:** 22.11.2025  

## Стиль API та Контракт

1. **Стиль API**  
   Ми використовуємо RESTful стиль для комунікації між клієнтом та сервером.  
   *Приклад:* `GET /accounts`, `GET /accounts/{id}`.

2. **Тип Медіа**  
   Усі запити та відповіді передаються у форматі `application/json`.  
   *Приклад:* заголовок `Content-Type: application/json`.

3. **Версіонування API**  
   На поточному етапі версіонування не використовується (implicit v1).  
   *Приклад:* `/api/accounts`.

4. **Відповідність OpenAPI-специфікації**  
   Усі публічні ендпоїнти повинні строго відповідати контракту, визначеному у файлі `docs/api/openapi.yaml`.  
   DTO, параметри, структура відповідей і статуси мають збігатися зі специфікацією.

## Політика Кодів Відповіді (HTTP Status Codes)

#### 2.1. Успішні відповіді
- **200 OK** — успішне отримання або оновлення ресурсу.  
  *Приклад:* `GET /accounts`.

- **201 Created** — успішне створення нового ресурсу.  
  *Приклад:* `POST /accounts`.

- **204 No Content** — ресурс успішно видалено; відповідь не містить тіла.  
  *Приклад:* `DELETE /accounts/{id}`.

#### 2.2. Клієнтські помилки
- **400 Bad Request** — неправильний або некоректний запит (у т.ч. помилки валідації).  
  *Приклад:* поле `amount` < 0.

- **401 Unauthorized** — користувач не автентифікований.  
  *Приклад:* відсутній токен.

- **403 Forbidden** — автентифікація пройдена, але прав доступу немає.  
  *Приклад:* спроба видалення чужого рахунку.

- **404 Not Found** — ресурс не знайдено.  
  *Приклад:* `GET /accounts/999`.

#### 2.3. Серверні помилки
- **500 Internal Server Error** — непередбачувана помилка на сервері.  
  *Приклад:* збій підключення до бази даних.

## Єдина Модель Помилок (Error Model)

Усі помилки, окрім відповідей зі статусами `204`, `401`, `403` та окремих випадків `500`, повертаються у єдиному форматі JSON, визначеному в `ErrorResponseDto.php`.

#### 3.1. Структура формату помилки

1. **error (string)**  
   Загальний клас помилки.  
   *Приклади:*  
   - `"ValidationError"`  
   - `"NotFoundException"`  

2. **code (string)**  
   Унікальний, машиночитаний код помилки, що використовується клієнтом.

3. **details (array)**  
   Масив деталей. Використовується насамперед у випадках валідації.  
   Елемент масиву містить:  
   - `field` — назва поля;  
   - `message` — опис проблеми.

{
    "error": "ValidationFailed",
    "details": ""
